Hemo OS documentation

How to install Hemo, drive it day to day, and fix the things that trip people up. Hemo is a Kali-based OS for security professionals that you rebuild for every engagement: pick a role and only that discipline's tools install.

Getting started

Hemo ships as a ready-to-run VMware virtual machine image (OVA). Give the VM 8 GB of RAM and turn on 3D acceleration, and take a snapshot after your first login so you can roll back.

  1. Download the image

    From the latest release, download every part of the .ova image. It is split into .7z.001, .7z.002… parts to stay under GitHub's file size limit. To check the download, keep SHA256SUMS, SHA256SUMS.minisig and hemo-release.pub next to the parts.

    minisign -Vm SHA256SUMS -p hemo-release.pub && sha256sum -c --ignore-missing SHA256SUMS

    Already on a Hemo box? Run hemo-verify in the download folder instead. It checks the signature with the key baked into the system, not the copy that came with the download.

  2. Extract and import

    Open the .001 part with 7-Zip on Windows, or run 7z x on it on Linux or macOS; the other parts are read automatically. Then open the .ova in VMware Workstation, Player or Fusion to import it.

    7z x hemo-<version>-vmware.ova.7z.001

  3. Log in

    Log in as hemo with the password hemo, just like Kali's kali/kali. You aren't forced to change it; do it with passwd when you're ready.

  4. Pick your roles

    Hemo Welcome opens automatically. Tick the roles the job needs; their tools install from the internet. The first role you pick is your primary and sets the wallpaper, accent and bookmarks.

  5. Make it yours

    On a clone, rename the machine and switch the look whenever you like.

    sudo hemo-identity james office hemo-theme red_team
Keep your engagement data on a separate disk, work from a linked clone of the imported VM, and delete the clone when the job ends.

Everyday use

Add a role later

Install another discipline's tools any time.

sudo hemo-roles

Switch the look

Re-skin to a role you already have, without installing anything.

hemo-theme blue_host

Set your target

Put the target in the bar and the prompt. It lives in a file, never an exported variable, so t prints it when you need it.

hemo-target 10.10.10.5 nmap -sV "$(t)"

Capture for the report

Frame the active window identically every time, straight to the clipboard.

shot # or Super+Print

Match the team's screenshots

Flip the whole desktop to the shared standard, then back.

hemo-report toggle # Super+P

Catch callbacks

Drop the roaming firewall before you need reverse shells.

sudo hemo-harden off

Keep it awake

Stop the lock and suspend during a long crack or scan.

hemo-caffeine on # Super+Shift+C

Record the build

Write down exactly what's installed, for the engagement record.

hemo-bom

Open PowerShell

A second shell with the same themed prompt as zsh.

hemo-pwsh # Super+Shift+Enter

Engagements

Each client gets its own folder under ~/engagements/. Make one active and everything that saves evidence (screenshots, the bill of materials, notes, terminal logs) lands in it. eng is short for hemo-engagement; both work.

Start a client

Creates scope, loot, scans, notes, creds and screenshots, records a baseline bill of materials, and makes it active.

eng new acme-corp

Switch clients

Points screenshots, notes and logs at the other client and brings back its saved target.

eng use other-client eng # which one am I on?

Note what happened

Adds a timestamped line to notes/timeline.md.

eng log "pivoted to DC01 via WinRM" tail "$(eng path)/notes/timeline.md"

Log the terminal

In tmux, Ctrl+b then Shift+H starts a transcript of the pane in the engagement's tmux-logs/. Switch engagements mid-session and the rest of the output follows you. Press it again to stop.

tmux new -s acme

Time every command

While an engagement is active, a dated line prints before each command runs, so logs and screenshots carry the time. Pick the date, time and time zone in Settings → Appearance.

hemo-appearance set date iso hemo-appearance set time 24h-tz hemo-appearance set tz est

Serve files to a target

Starts a file server on your VPN address (LAN if no VPN), with upload on, and copies a fetch one-liner to the clipboard. Serves the engagement's loot/ by default.

hemo-serve hemo-serve --tls # or --webdav, --smb

Wrap up

Records a final bill of materials and clears the active engagement. Nothing is deleted.

eng close

What the prompt shows

Every prompt shows @client while an engagement is active. Pick the Engagement prompt in Settings → Appearance to also see the IP a target would see from you, and the current target:

@acme-corp 󰒃 10.10.14.42 → 10.10.10.5 ~ ❯

The IP is green with a shield when a VPN is up. When it isn't, it turns yellow and shows your public address instead, so a dropped tunnel is obvious on the next prompt.

Hemo keeps the engagement and target in files under ~/.config/hemo/ and never exports them as environment variables, so they don't show up in env, aren't inherited by tools, and don't travel over SSH.

Heavy services (local Docker stacks)

hemo-bloodhound

BloodHound Community Edition, the AD attack-path graph. The web UI is bound to localhost.

hemo-bloodhound uphemo-bloodhound urlhemo-bloodhound passwordhemo-bloodhound down
hemo-arkime

Arkime full-packet PCAP indexing and search, for offline analysis.

hemo-arkime uphemo-arkime inithemo-arkime import <file.pcap>hemo-arkime down
hemo-elk

A local log-analytics stack (OpenSearch or Elasticsearch), bound to localhost.

hemo-elk uphemo-elk ingest <file>hemo-elk down
hemo-adaptix

Build and run the AdaptixC2 teamserver in Docker, and launch its client on the host.

hemo-adaptix uphemo-adaptix clienthemo-adaptix down
Each service's data lives in named volumes and survives down. destroy deletes it, and asks first. BloodHound, Arkime and the ELK stack all want roughly 8 GB, so run only one at a time.

Troubleshooting

The things people hit most often, and the fix for each.

Apps are slow to open and the desktop feels sluggish

Why 3D acceleration is off, so the screen is drawn on the CPU.

Fix Power off the VM. In VMware, open Settings → Display and tick Accelerate 3D graphics (1 GB of graphics memory is plenty), then boot again. A cold Firefox launch drops to about a second.

Reverse shells, Responder or SMB catchers get no callbacks

Why The roaming firewall is on and dropping inbound connections.

Fix Turn it off for the engagement with sudo hemo-harden off, and back on with sudo hemo-harden on when you are on an untrusted network. Check the state with hemo-harden status. It is off by default.

No tools installed after first boot

Why Roles install their tools over the internet when you pick them, and the box had no network.

Fix Once you are online, run sudo hemo-roles, or open Hemo Welcome and install roles there.

The theme change didn't reach Firefox, Neovim or GTK apps

Why These apps read their theme only when they start.

Fix Fully quit and reopen the app. Close Cherrytree before switching themes, because it rewrites its config on exit.

Clipboard, drag-and-drop or window resizing with the host doesn't work

Why VMware Tools starts at login, and the session hadn't picked it up.

Fix Log out and back in. Hemo bakes in VMware Tools (open-vm-tools) and starts it automatically.

Flameshot captures come out blank

Why Flameshot needs the legacy X11 capture path on i3.

Fix Hemo sets useX11LegacyScreenshot=true and reapplies it on every theme change, so this is already handled. If you ever see it, set that key in ~/.config/flameshot/flameshot.ini and restart Flameshot.

You want Hemo Welcome to open again

Why It opens at login only until you finish setup.

Fix Run hemo-welcome any time, press Super+Shift+D, or use “Run setup again” in Settings.

You need to rename the machine from hemo@hemo

Why Linux can't rename a user who has running processes.

Fix Run sudo hemo-identity <user> <host> right after first boot, from a fresh text console (Ctrl+Alt+F2), or add --force.

Importing a VPN profile hangs

Why The minimal i3 build has no graphical file picker for the dialog.

Fix Import from the command line instead, for example nmcli connection import type openvpn file client.ovpn. The connection then appears in the network menu.

Starting BloodHound, and finding its password

Why BloodHound CE runs as a local container stack.

Fix Run hemo-bloodhound up (the first run downloads it), then hemo-bloodhound url for the address and hemo-bloodhound password for the admin password.

The app launcher is full of Kali “-h” help entries

Why Kali ships a launcher entry for every tool's help text.

Fix Run sudo hemo-menu-tidy to hide them, or hemo-menu-tidy --undo to bring them back.

The screen locks or the VM suspends during a long job

Why Idle locking and suspend are on by default.

Fix Press Super+Shift+C, or run hemo-caffeine on, to keep the session awake until you turn it back off.

Windows stack up or go tabbed after a stray key

Why Super+S and Super+W switch the container to a stacked or tabbed layout.

Fix Press Super+E to return to the normal split layout.

No date line prints before commands

Why The stamp only prints while an engagement is active, in a shell started after it was turned on.

Fix Run eng use <client>, then open a new terminal or run exec zsh. Check that Stamp date and Stamp time aren't both Off in Settings → Appearance. HEMO_STAMP=0 turns it off for one shell.

The IP in the prompt turned yellow

Why No VPN is up, so the prompt shows your public address, which is what a target on the internet would see.

Fix Reconnect the VPN from the network menu. The prompt goes back to the green shield on the next command. To stop the public-address lookup entirely, run touch ~/.config/hemo/no-egress.

The tmux log is missing or in the wrong folder

Why Logging writes to the active engagement's tmux-logs/, or to ~/engagements/tmux-logs/ when none is active.

Fix Check the active one with eng, then ls "$(eng logdir)". The line where you ran eng use stays in the old engagement's log; everything after it goes to the new one.

Firefox can't save a file outside Downloads

Why Firefox runs in a sandbox that only allows writes to Downloads and its own profile.

Fix Save to Downloads, or launch once with HEMO_NO_SANDBOX=1 firefox-esr when you need the full filesystem.
